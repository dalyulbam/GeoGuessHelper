여섯 번 고쳤다고 말했고, 여섯 번 다 틀렸다

검은 로드뷰 하나를 두고 여섯 번 구현 완료를 선언했다. 일곱 번째에야 원인이 드러났고, 그것은 첫 진단이 틀렸다는 뜻이었다. 이 문서는 그 여섯 번이 각각 무엇을 고쳤고 무엇을 못 봤는지, 그리고 왜 매번 완료라고 말할 수 있었는지를 적는다. 같은 병이 번역 실패에서도 그대로 반복됐다.

3. 왜 매번 “완료”라고 말할 수 있었나

거짓말이 아니었다. 매번 측정이 있었다. 그 측정이 무엇을 재고 있었는가가 문제다.

① 내가 만든 것을 내가 만든 것과 비교했다

v0.3.0 에서 구형 뷰어를 우리 서버가 만든 URL 과 대조해 평균차 1.29 로 “일치” 판정했다. 둘 다 같은 pitch 부호 오류를 갖고 있어 나란히 틀렸을 뿐이었다. 진짜 기준은 구글이 링크에 넣어 준 !6s 썸네일이었고, 그것과 대면 37.24 였다.

규칙: 대조 대상은 내가 만든 것이 아니어야 한다.

② 증상이 아니라 기능을 쟀다

v0.3.0 에서 회전을 pano.setPov() 를 코드로 불러 확인했다. 배선(시점→다시 그리기)은 증명했지만 사람이 잡아 끌 수 있는지는 전혀 증명하지 않았다. 오버레이는 pointer-events:none 이었다.

규칙: 지표는 기능이 아니라 신고를 따라간다. “검다”에는 밝기를, “안 바뀐다”에는 화면 지문의 차이를 잰다.

③ 부정 결과를 사실로 받아들였다

ZERO_RESULTS 를 “그런 파노는 없다”로 읽었다. 실제로는 “내가 준 형식으로는 못 찾는다”였다. 같은 실수를 이 프로젝트에서 네 번 했다 — 호스트 필터, 워커 타임라인, 포트/경로, 그리고 이것.

규칙: 부정 결과는 스스로를 증명하지 않는다. 결론 전에 질의 방식을 의심한다.

④ 한 번 세운 전제를 다시 재지 않았다

v0.2.4 의 “SDK 미제공” 판정을 이후 세 판 동안 주어진 사실로 취급했다. 그 전제를 다시 쟀다면 좌표 조회가 돌려주는 CAoS… id 를 봤을 것이고, 거기서 원래 id 가 그대로 나온다는 것도 봤을 것이다.

규칙: 같은 증상이 반복되면 고친 것이 아니라 전제를 다시 잰다.

4. 일곱 번째 — 진짜 원인

전제를 다시 재기로 하자 5분 만에 나왔다.

사용자가 CIABIhC3KIRGTQtfjhRG2LU3AfZw 를 신고했다. 스크린샷의 버전 배지가 v0.3.2 였다 — 버전 문제가 아님을 즉시 배제할 수 있었다 (그 배지는 v0.3.2 에서 “재현 안 되는 신고”에 지쳐 넣은 것이다). 그리고 화면에 © Radovan Findra 와 장소명이 떠 있었다 — 파노는 로드돼 있었다.

그래서 ID 조회와 좌표 조회를 나란히 다시 쟀다.

CIHM0ogKEICAgIDqvbDfZw
    ID 조회   : ZERO_RESULTS
    좌표 조회 : OK  pano=CAoSFkNJSE0wb2dLRUlDQWdJRHF2YkRmWnc.  © Gerd Rammelsberger

좌표로는 찾아진다. 그리고 돌아온 id 가 낯익었다 — base64 로 디코드해 봤다.

b"\x08\n\x12\x16" + b"CIHM0ogKEICAgIDqvbDfZw"
같은 파노의 다른 옷이었다. protobuf 봉투(필드1=10, 필드2=길이지정 문자열) 안에 원래 id 가 통째로 들어 있다. 그러면 우리가 직접 감싸면 된다 — 좌표 조회도, 대체 파노도, 오버레이도 필요 없다.
def wrap_pano_id(pid):
    raw = bytes([0x08, 0x0A, 0x12, len(pid)]) + pid.encode("ascii")
    return base64.b64encode(raw).decode().replace("+","-").replace("/","_").replace("=",".")

실측: 세 파노 모두 ZERO_RESULTS → OK. 신고 링크의 화면 밝기는 검정 → 129.1 이 됐고, 오버레이가 아니라 진짜 구글 파노라마라 드래그·줌·이동이 전부 네이티브로 동작한다.

7. 공통 병과 처방

병: 조용한 폴백. 실패했는데 그럴듯한 값을 돌려주면, 그 위의 모든 것이 정상처럼 흘러간다. 로그에도 화면에도 흔적이 없다.

이번에 코드로 굳힌 처방:

처방어디에
실패를 구조화해 반환한다 translate_texts(stats=…) — requested/translated/failed_chunks/errors
반환값이 아니라 효과를 검사한다 server 가 실제 번역 건수를 보고, 0 이면 errors 에 적는다
독자에게도 말한다 보고서 상단 .pf-note.warn — “번역에 실패해 원문 그대로입니다”
정적 결함은 import 시점에 드러낸다 i18n._assert_label_parity() — 라벨을 추가하면 그 자리에서 걸린다
실행 중인 코드를 화면에 박는다 우하단 버전 배지 + index.html no-store
덮은 것은 같은 자리에서 걷는다 clearFallback() 이 오버레이·뷰어·타이머를 함께 정리
