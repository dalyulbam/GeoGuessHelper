논란 많은 강역은 기계가 긋지 않는다 —
사람이 긋고, 지도는 그것이 사람의 주장임을 밝힌다

그라나다 왕국, 청나라, 한나라, 달마티아 민족 분포 — 역사적 국경과 민족의 경계는 사료마다, 시기마다, 관점마다 다르다. LLM 지오코딩 금지 원칙(없는 좌표를 지어내는 순간 아틀라스가 거짓말을 한다)은 강역 폴리곤에도 그대로 적용된다. 그래서 이 시스템의 답은 하나다: 사용자가 마우스로 직접 그린다. 그린 것은 원자와 같은 사실이 아니라 서명된 주장으로 저장되고, 지도는 그 둘을 절대 섞지 않는다.

패스 없음 — LLM 무관여 사이드카 원칙 유지 시간·연관 렌즈 연동 백엔드 최초의 쓰기 API
문제

점 앵커는 나라를 말하지 못한다

지금 아틀라스의 행위자는 전부 점이다 — 원자 좌표의 중앙값 하나. 도시는 점으로 충분하지만 정치체·문화권은 면이다. 그리고 그 면이야말로 가장 논란이 많다.

👑정치체의 강역

그라나다 왕국은 1232–1492 사이 계속 줄어들었다. 청나라의 "강역"은 1644년과 1820년이 전혀 다르고, 신장·티베트 포함 여부는 지금도 정치적 논쟁이다. 하나의 정답 폴리곤은 없다 — 시기와 관점이 붙은 여러 판본이 있을 뿐이다.

🗣민족·문화의 분포

달마티아 "민족"의 분포는 국경보다 더 흐리다 — 언어 경계는 마을 단위로 섞이고, 사료는 서로 다르게 긋는다. 경계선이 아니라 번짐(gradient)이 본질인 대상을 폴리곤으로 그릴 때는 그 한계가 화면에 보여야 한다.

🤖왜 기계가 못 긋는가

LLM 에게 "청나라 국경 좌표"를 물으면 무언가는 나온다 — 그게 문제다. 출처도 시점도 없는 그럴듯한 다각형은 지도 전체의 신뢰를 무너뜨린다. 국가 앵커를 Natural Earth 폴리곤 중심으로만 단 것과 같은 이유로, 강역은 사람 손 아니면 없다.

원칙의 확장. 기존 원칙 — 관계는 원자 본문이 명시적으로 서술한 것만, 좌표는 실측·공개 데이터만. 새 원칙 — 강역은 사람이 그린 것만, 그린 사람·날짜·근거·시기가 함께 저장되고, 화면에서는 점선 테두리와 ✍ 표시로 "주장"임을 항상 밝힌다. 원자에서 유도된 것(사실)과 사람이 그린 것(주장)은 스타일·툴팁·패널 어디서도 섞이지 않는다.

지목된 네 대상의 현재 상태

계획은 실측 위에 선다 — 사용자가 예로 든 행위자들을 오늘의 대장에서 찾아본 결과다.

데이터 계약

GeoJSON 사이드카 — 행위자당 한 파일, 판본은 Feature

저장 형식은 표준 GeoJSON 이다 — QGIS·geojson.io 로 열리고, git diff 로 읽히고, 뷰어가 이미 쓰는 world.geo.json 과 같은 문법이다. 위치는 altaiya/data/territories/{slug}.geojson.

{
  "type": "FeatureCollection",
  "slug": "kingdom-of-granada",      // 대장 조인 키 — 없으면 강역 전용 행위자가 된다
  "label": "그라나다 왕국",             // 대장에 없을 때 쓸 표시명
  "features": [{
    "type": "Feature",
    "geometry": { "type": "MultiPolygon", "coordinates": [ … ] },  // [lng,lat] — 섬·비지 허용
    "properties": {
      "claim":    "최대 강역",        // 판본 이름 — "핵심부"·"1264년 시점"·"헤르더 기준 분포" …
      "period":   [1232, 1492],       // 시간 렌즈가 이 창과 교차 판정한다
      "basis":    "…근거 메모·출처…",  // 왜 이렇게 그었는가 — 빈 값 금지
      "disputed": true,               // 논란 표시 — 빗금 채움으로 렌더
      "drawn_by": "dalyulbam",
      "drawn_at": "2026-08-26",
      "rev":      1                   // 저장마다 +1 — 덮어쓰기 사고 방지
    }
  }]
}

📐왜 행위자당 한 파일인가

git 이 역사를 지킨다 — 강역 수정은 파일 하나의 diff 로 보이고, 잘못 그으면 되돌린다. 판본(claim)이 늘어도 파일은 하나라 조인이 단순하다.

🕰왜 판본이 1급인가

"청나라 강역"의 정답은 없고 1644년 판본과 1820년 판본이 있다. 판본마다 period 가 붙으므로 시간 렌즈를 돌리면 강역이 자라고 줄어드는 게 그대로 보인다.

✍왜 basis 가 필수인가

원자에 quote 없는 관계를 긋지 않는 것과 같다 — 근거 메모 없는 폴리곤은 저장을 거부한다. 한 줄이어도 좋다: "위키피디아 1264년 지도 눈대중". 그게 있어야 훗날의 내가 믿는다.

아키텍처

읽기는 조인, 쓰기는 최초의 POST 한 개

기존 구조(원자 불변 · 사이드카 · 빌드 산출물)는 그대로다. 강역은 세 번째 사이드카로 들어와 빌드 때 조인되고, 에디터의 저장만이 백엔드 최초의 쓰기 경로가 된다.

구성 요소변경내용
atlas.py (빌드)확장 territories/ 를 스캔해 슬러그로 행위자에 붙인다. 대장에 없는 슬러그면 강역 전용 행위자를 만든다 — type=polity · atom_count=0 · basis="hand-drawn" · 백과에 "원자 0 · 강역만" 으로 정직하게 표시. 무장소 행위자가 강역을 얻으면 본토 최대 링의 중심을 앵커로 승격한다(국가 폴리곤 앵커와 같은 계산 — 결정론·재현 가능).
app.py (API)추가 2 GET /api/territories — 전체 강역(뷰어 초기 로드).
POST /api/territory/{slug} — 에디터 저장. 검증: 링 최소 3점 · basis 비어 있으면 400 · rev 가 파일보다 낮으면 409(동시 편집 보호). 로컬 서버라 인증은 없지만 쓰기는 이 한 경로뿐이다.
app.js (뷰어)추가 SVG 레이어 #g-territory 를 국경선(g-world)과 격자 사이에 깐다 — 마커·관계선 아래, 배경 위. 채움은 행위자 유형색 10%, 테두리는 점선(주장의 시각 언어), disputed 는 빗금 패턴 추가. 클릭 → 행위자 선택, 호버 → 툴팁에 claim·시기·근거·✍서명.
렌즈 연동자동 시간 렌즈: Feature.period ∩ 창 — 교차하는 판본만 그린다(창을 긁으면 강역이 커졌다 작아진다). 연관 렌즈: 행위자가 집합 밖이면 강역도 걷는다. 테마·시대 렌즈: 행위자 가시성을 그대로 따른다 — 규칙을 새로 만들지 않는다.
에디터 UX

그리기 모드 — 지도는 그대로, 손끝만 바뀐다

진입은 두 곳: 상세 패널의 ✍ 강역 그리기 칩(행위자 있음), 백과 하단의 새 강역 버튼(청나라처럼 행위자 없음 — 슬러그·표시명을 물은 뒤 시작). 진입하면 리본이 에디터 상태를 잡고, 저장·취소 전까지 다른 조작을 잠근다.

조작동작
클릭꼭짓점 추가 — 지도 팬·줌(휠·드래그)은 그리는 중에도 그대로 산다
첫 점 클릭 · Enter링 닫기 — 이어서 "새 링"으로 섬·비지 추가 가능
Backspace마지막 꼭짓점 무르기
꼭짓점 드래그이동 · 변 중점 클릭 → 사이에 꼭짓점 삽입 · Alt+클릭 → 삭제
Esc취소 — 그리던 것을 버리고 에디터를 나간다(확인 후)
저장판본 이름·시기·근거·disputed 를 묻는 작은 폼 → POST → 즉시 지도 반영

리본이 에디터 상태를 잡는다(문명5 ActionInfoPanel 문법 그대로). 흰 점 = 드래그 중인 꼭짓점, 변 위 작은 원 = 중점 삽입 지점, 점선 = "이것은 주장"의 시각 언어.

개발 계획

5단계 — 각 단계가 독립 검증 가능

단계산출물끝났음을 아는 방법
1계약 + 표시
(에디터 없이)		 GeoJSON 스키마 확정 · atlas.py 조인 · GET API · #g-territory 렌더 · 렌즈 연동 손으로 쓴 kingdom-of-granada.geojson 샘플이 지도에 점선 폴리곤으로 뜨고, 시간 창을 1500 이후로 옮기면 사라진다
2에디터 — 그리기 그리기 모드 진입·꼭짓점 추가·링 닫기·메타 폼·POST 저장·rev 검사 그라나다 강역을 마우스로 그려 저장하면 파일이 생기고, 새로고침 없이 지도에 남으며, git diff 에 사람이 읽을 수 있는 좌표 변경이 보인다
3에디터 — 수정 꼭짓점 드래그·중점 삽입·Alt 삭제·다중 링(섬)·판본 추가·삭제 저장된 강역을 다시 열어 해안선을 다듬고, "핵심부" 판본을 추가로 그려 두 판본이 시간 렌즈에서 다르게 나타난다
4강역 전용 행위자 + 앵커 승격 대장에 없는 슬러그 처리 · 무장소 행위자의 강역 중심 앵커 대장에 없는 청나라를 새 강역으로 그리면 지도와 백과에 "원자 0 · 강역만"으로 서고, 훗날 원자가 생기면 같은 슬러그로 합쳐진다
5백과·패널 통합 패널에 판본 목록(claim·시기·근거·서명) · 백과에 ✍ 표시 · /api/actor 확장 행위자 패널에서 판본을 켜고 끄며, 각 판본의 근거 메모를 원자 인용과 나란히 — 그러나 구분되게 — 읽을 수 있다

규모 감각: 1단계 ~150줄(파이썬 60 · JS 90) · 2단계 ~200줄 · 3단계 ~150줄 · 4단계 ~80줄 · 5단계 ~100줄. 전부 기존 파일 확장이고 새 라이브러리는 없다 — 좌표 변환(px/py)·SVG 레이어·리본·렌즈 파이프라인이 이미 있어 에디터는 그 위에 얹힌다.

검증 기준

"됐다"를 판정 가능한 문장으로

V1왕복 무손실 — 그리고 저장한 폴리곤을 다시 열어 저장해도 파일 diff 가 0이다 (rev 만 +1)
V2주장 표시 — 강역이 있는 모든 화면(지도·툴팁·패널·백과)에서 ✍·점선·서명 중 하나 이상이 보인다. 원자 유도 데이터와 같은 스타일로 그려지는 곳이 한 군데도 없다
V3시간 정합 — 그라나다 [1232,1492] 판본은 시간 창 [1500,1800] 에서 보이지 않고, [1300,1400] 에서 보인다. 달마티아 로마/근대 판본이 같은 창에 함께 뜨지 않는다
V4선행 강역 — 대장에 없는 슬러그(청나라)로 강역을 만들 수 있고, 그 행위자의 백과 항목이 "원자 0"을 숨기지 않는다
V5거부 동작 — basis 빈 저장, 3점 미만 링, 낮은 rev 저장이 각각 400/400/409 로 거부되고 에디터가 이유를 말해 준다
V6실사용 — 사용자가 그라나다 왕국 최대 강역을 5분 안에 그려 저장하고, 시간 렌즈를 돌려 "1492 이후 사라짐"을 확인한다 — 통과/보완은 사용자가 판정

🚫정답 주장

그린 폴리곤은 "실제 국경"이 아니라 "이 사용자가 이 근거로 이렇게 본다"다. 정확성 검증·역사학적 판정은 범위 밖이다.

🚫LLM 관여

제안·자동 보정·스냅 추천 등 어떤 형태로도 모델이 좌표를 만들지 않는다. 훗날 넣더라도 별도 기획으로 다시 논한다.

🚫번짐의 표현

민족 분포의 gradient 는 1차 범위에서 다각형 + disputed 빗금으로 근사한다. 농도 지도(heatmap)는 하지 않는다 — 필요해지면 판본을 여러 개 그리는 것으로 대신한다.
