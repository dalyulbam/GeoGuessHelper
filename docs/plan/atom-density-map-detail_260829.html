진단

세 가지 병목은 한 줄로 묶인다 — "보고서가 남기는 것이 너무 굵다"

🧩범주가 굵다

"경제" 레이어 하나에 조선소·양조장·리튬 광산·크루즈 관광이 다 들어간다. 주식 테마 렌즈가 그 중에서 상장기업만 남기고 싶어도 레이어로는 못 가른다. 범주는 렌즈의 재료다 — 범주가 없으면 렌즈는 근사에 머문다.

📉원자가 적다

적재 프롬프트가 "장소를 요약하라"에 가깝다. 요약은 사실을 합치고, 원자는 사실을 가른다. 8개 상한은 본래 비용·시간 가드였는데, 지금은 보고서 한 건($1.3)의 결과물을 8문장으로 줄이는 병목이 됐다.

🗺️좌표가 하나다

캡처마다 로드뷰 좌표(pano lat/lng)와 방위가 있는데, 원자는 전부 보고서 시작점에 찍힌다. 지점 단서는 그 캡처의 좌표를 받아야 확대 지도에서 살아난다. 좌표는 이미 있다 — 잇지 않았을 뿐이다.

원칙은 그대로다. 원자는 여전히 보고서(분석·리서치)에서만 태어나고, 좌표는 실측(로드뷰 pano 좌표·Static 메타)에서만 온다 — LLM 지오코딩 금지. 늘리는 것은 추출의 해상도이지 추측의 허용이 아니다. 범주도 모델이 짓지 않는다 — 닫힌 어휘에서 고르고, 못 고르면 other + 태그로 남긴다(관계 유형의 related와 같은 규칙).

📐스키마 변경 — 최소

  • Atom.category: str 추가(선택). 없는 기존 원자는 other로 읽힌다 — 마이그레이션 없음.

  • altaiya rules.THEME_MATRIX 에 범주 가중을 덧붙인다(레이어 가중은 폴백으로 유지).

🧪어휘를 고정하는 방법

  • 기존 원자 297건(보고서 유래)을 범주 어휘로 1회 재분류(LLM, ≈$0.5). 각 범주에 실례가 최소 3개 없으면 어휘에서 뺀다.
  • 범주 분포가 한 칸에 30% 이상 몰리면 그 칸을 쪼갠다 — 지금의 "경제"가 그 예다.
  • 어휘 변경은 기획서 개정으로만 — 코드에서 즉흥적으로 늘리지 않는다.

🔁중복은 병합으로

원자가 4배 늘면 중복도 는다. 지금의 _find_near_duplicate(레이어·엔티티·태그·스코프 근사)에 범주를 조건으로 더하고, 같은 셀·같은 범주·제목 유사도 0.8 이상이면 병합한다. 병합은 uses를 올려 회상 점수에 남는다 — 지워지는 것은 없다.

⏱예산 밖에서 돈다

P1·P3 는 보고서 응답 뒤에 백그라운드로 돈다(지금의 300초 예산 밖). 실패하면 ingest --scan 이 결손으로 잡아 사후 적재한다 — 오늘 만든 백필 경로를 그대로 쓴다.

🧾기존 57건 소급

잡 로그에 primaryAnalysis가 남은 보고서는 P1·P2 를 소급할 수 있다(캡처 좌표는 result.images 와 captures/ 메타에서). 소급 1회 ≈ $15. 리서치 프로파일은 잡 로그에 없어 P3 소급은 앞으로의 보고서부터다 — 그래서 결과 JSON 에 프로파일을 남기는 것이 선행 작업이다.

⚠ 밀도는 회상(recall)에도 압력을 준다. 오늘 회상 필터를 고쳤지만(전역 원자 무조건 통과 폐지), 원자가 5천 개가 되면 점수식만으로는 부족하다. P1 지점 원자는 같은 5자 셀 안에서만 회상되게 스코프 규칙을 지키고, 회상 상한(12)은 범주별 상한(cue 4 · 장소 4 · 프로파일 4)으로 나눈다.

🧭왜 원자를 마커로 올리나

행위자는 원자 좌표의 중앙값 한 점이다. 확대하면 그 중앙값 주위에 실제 관측 지점들이 흩어져 있어야 "이 도시는 이 골목들에서 이렇게 읽혔다"가 보인다. 원자가 마커가 되면 지도가 곧 증거 목록이 된다 — 관계선이 전부 원자를 인용하는 것과 같은 정직성이다.

📦왜 사료권 단위로 자르나

세계 전체 10m 벡터는 수십 MB 다. 사료권(50개)은 이미 원자가 있는 곳만 덮으므로, 그 bbox 로 자르면 한 사료권에 100~300KB — 뷰어는 사료권을 선택하거나 그 안으로 줌인할 때만 받는다. 원자가 없는 곳은 배경도 굵다 — 커버리지와 같은 말을 지도 배경이 한다.

지형 데이터

구글맵에서 지형을 가져오는 방법 — 되는 것, 안 되는 것, 대신 쓰는 것

"구글맵에 지형이 있으니 그걸 쓰자"는 세 가지로 갈린다. 표시(보여주기)는 되고, 추출(우리 SVG 로 다시 그리기·저장)은 안 되며, 숫자 데이터(고도)는 조건부다. README 의 ToS 절(캡처는 로컬·임시·비재배포, durable key 는 lat/lng)과 같은 선에서 정리한다.

Maps JavaScript API — mapTypeId: 'terrain'구글의 지형 음영·등고 타일을 구글 지도 안에 표시 허용 — 구글 지도 위젯 안에서 보여주는 것은 정상 사용. 금지 — 타일을 받아 저장·재조합·다른 지도에 얹기(3.2.3 프리페치/캐시/스크래핑 금지, 콘텐츠를 구글 지도 밖에서 사용 금지) 본체 2분할 지도에 지형 토글(hybrid ↔ terrain). 가장 싸고 즉시 되는 것 — 캡처 합성 지도에도 지형 타입을 쓸 수 있다(Static Maps maptype=terrain, 이미지는 지금처럼 로컬·임시). 아틀라스 SVG 에는 못 올린다.

# altaiya/altaiya-backend/terrain.py (신규) — 읽기 전용 원자, 쓰기는 data/terrain/ 뿐
uv run --project E:\GeoguessHelper python altaiya\altaiya-backend\terrain.py build --sphere south-east-adriatic
  1. 사료권 bbox(+여백 15%) → 슬리피 타일 z=8 목록 (대개 4~16장)
  2. curl 로 Terrarium PNG 수신 → 고도 = (R·256 + G + B/256) − 32768  # 저장하지 않는다, 계산만
  3. hillshade(태양 315°/45°) → 사료권 bbox 로 자른 PNG(≤ 200KB) → data/terrain/{sphere}.hillshade.png
  4. 등고선 100m 간격(도시권 사료권은 50m) → Douglas–Peucker 단순화 → data/terrain/{sphere}.contours.json
  5. Natural Earth 10m 벡터를 같은 bbox 로 잘라 data/terrain/{sphere}.vector.json
  6. meta: 출처·타일 z·생성 시각·라이선스 문자열 → 뷰어 범례가 그대로 표시
# 뷰어: 사료권 선택 또는 그 bbox 로 줌인(k ≥ 2) 시 fetch, #g-terrain(g-world 아래) 에 image + path

🧊왜 래스터 + 벡터 둘 다인가

음영은 래스터가 싸고(PNG 한 장), 등고선은 벡터라야 줌에서 깨지지 않는다. 둘 다 사료권당 300KB 안쪽이면 배포본(Railway)에 실어도 4.8MB 스냅샷 옆에서 부담이 없다.

🧾출처는 화면에

범례에 "지형: Copernicus GLO-30 (ESA) · 해안선: Natural Earth"를 상시 표기한다. 오픈 데이터도 출처 표기가 조건이다 — 원자에 출처 URL 을 붙이는 것과 같은 규칙.

🛑없으면 없는 대로

지형 파일이 없는 사료권은 지금처럼 110m 해안선만 그린다. 뷰어는 어느 사료권에 지형이 있는지 meta.terrain 으로 밝힌다 — 침묵 폴백 금지.

🚫구글 지형의 추출

타일·고도 격자를 받아 저장하고 우리 지도에 다시 그리지 않는다. 구글 지형은 구글 지도 안에서만 본다.

🚫LLM 지오코딩

원자 좌표는 캡처 pano 좌표·시작 좌표·국가 폴리곤 중심에서만 온다. "이 표지판은 아마 저 사거리"를 모델이 찍지 않는다.

🚫OSM 도로망

도로·건물은 1차 범위 밖이다. ODbL 의 파생 DB 공개 의무가 사이드카에 번지는 것을 먼저 판단해야 한다 — 별도 기획.

🚫범주의 즉흥 확장

모델이 낸 새 범주를 코드가 받아 주지 않는다. 어휘는 기획서 개정으로만 는다.

🚫기존 원자 소급 재작성
