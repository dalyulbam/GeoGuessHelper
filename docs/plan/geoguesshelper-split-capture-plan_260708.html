붙여넣은 구글맵 링크에서 카메라 포즈 뽑기

지오게서는 결과 화면에서 복사용 링크를 직접 주지 않는다 — 인게임 단축키 3이 정답 지점의 스트리트뷰 /@ URL을 새 탭으로 연다. 사용자는 그 URL(또는 공유 단축링크)을 붙여넣는다. 세 가지 형태를 하나의 파서로 받는다.

# https://www.google.com/maps/@51.5083663,-0.1114931,3a,75y,260.89h,78.32t/data=!3m5!1s<PANOID>!2e0!7i16384!8i8192
  lat = 51.5083663   lng = -0.1114931
  3a   # 카메라 고도 마커(~3m, 차량 높이). 포즈에는 불필요 — 무시
  75y  # 수직 FOV/줌(도). 기본 75, ~90=광각 … ~15=망원. 낮을수록 확대
  260.89h # heading(방위각) 0..360, 북=0 시계방향 → StreetView POV heading
  78.32t  # tilt. 90=수평. 실제 pitch = tilt - 90 = -11.68. pitch가 0이면 이 토큰은 사라짐(선택)
  !1s<PANOID>!2e0  # 파노라마 ID (뒤에 반드시 !2e0). !2e0 = Google 이미지
검증 노트(어드버서리). /@…/data= 형식은 Google이 공식 문서화하지 않은 리버스 엔지니어링이며 예고 없이 바뀔 수 있다. 따라서 파서는 관대하게 짠다 — t(tilt) 그룹은 선택, 정수/소수 혼용 허용, 3a 외 고도값 허용. 진짜로 안정적인 것이 필요하면 공식 api=1 형태와 Metadata API를 우선한다. pitch = tilt − 90 변환은 확인됨(tilt 90→0, 0→−90, 180→+90).

파노라마 ID 세 계열 — 형태로 분류

계열형태분류 규칙
공식 Google22자 base64url, 끝이 g/w/A/Q (예 jJXYsBpPPqWuvSR5RUaIEQ)^[A-Za-z0-9_-]{21}[gwAQ]$
레거시 3rd-party44자, AF1Qip… 시작 (사용자 포토스피어)^AF1Qip[A-Za-z0-9_-]{38}$
모던 3rd-party내부 id는 CIHM…, 인코딩 래퍼는 CAoS…(protobuf, type 10=비공식)"공식도 AF1Qip도 아님"으로 분류 — CAoS-only 정규식은 모던 raw id를 놓친다

세 계열 모두 StreetViewPanorama.setPano()·Static API pano=에 그대로 넣을 수 있어 대개 protobuf 디코딩은 불필요. 단, 렌더 실패 시 lat/lng + StreetViewService.getPanorama로 폴백한다.

파서 (linkresolver.py)

import re, httpx

_AT = re.compile(
    r"@(?P<lat>-?\d+\.\d+),(?P<lng>-?\d+\.\d+)"
    r"(?:,(?P<fov>\d+(?:\.\d+)?)y)?"       # 75y
    r"(?:,(?P<heading>-?\d+(?:\.\d+)?)h)?"   # 260.89h
    r"(?:,(?P<tilt>-?\d+(?:\.\d+)?)t)?")      # 78.32t (선택 — pitch 0이면 없음)
_PANO = re.compile(r"!1s(?P<pano>[^!?]+)")

async def resolve_short(url):
    if not re.search(r"(maps\.app\.goo\.gl|goo\.gl/maps)", url): return url
    ua = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) … Chrome/124"}
    async with httpx.AsyncClient(follow_redirects=True, headers=ua, timeout=10) as c:
        r = await c.get(url); r.raise_for_status()
        return str(r.url)   # 확장된 /@ URL (goo.gl 구링크는 404 가능 — graceful 처리)

def parse_pose(url):
    out = {"lat":None,"lng":None,"pano":None,"heading":None,"pitch":0.0,"fov":75.0}
    # api=1 폼 우선 파싱 → 없으면 /@ 폼
    m = _AT.search(url)
    if m:
        out["lat"],out["lng"] = float(m["lat"]),float(m["lng"])
        if m["fov"]:     out["fov"]=float(m["fov"])
        if m["heading"]: out["heading"]=float(m["heading"])
        if m["tilt"]:    out["pitch"]=float(m["tilt"])-90.0   # ← 핵심 변환
    p = _PANO.search(url)
    if p: out["pano"]=httpx.URL(url).params or unquote(p["pano"])
    if out["lat"] is None and out["pano"] is None: raise ValueError("좌표/파노 없음")
    return out   # panoId None이면 호출부가 StreetViewService.getPanorama로 폴백
단축링크 해제는 반드시 서버측. 브라우저는 CORS/opaque 리다이렉트로 maps.app.goo.gl을 못 푼다 — 카카오 SDK가 "등록 도메인에서만" 도는 것과 같은 결의 제약이다. 또 EU/UA 미설정 시 consent.google.com 동의 페이지가 뜰 수 있어, 최종 URL이 동의 페이지면 HTML의 og:url/rel=canonical/APP_INITIALIZATION_STATE에서 목적지를 복구한다.

카카오 Roadview의 전세계 대응물은 Maps JS API의 google.maps.StreetViewPanorama + google.maps.StreetViewService다. 위 div에 파노라마, 아래 div에 지도를 만들고 map.setStreetView(panorama)로 묶는다.

🧩 핵심 API 표면 (검증됨)

StreetViewPanorama(el, opts)position · pov{heading,pitch} · zoom · pano · visible · linksControl · motionTracking
메서드setPano/getPano · setPosition/getPosition · setPov/getPov · getPhotographerPov · getLinks · getZoom
이벤트position_changed · pov_changed · pano_changed · links_changed · status_changed
연결map.setStreetView(pano) / map.getStreetView()
최근접 파노StreetViewService.getPanorama(req) → Promise<StreetViewResponse> (data.location.pano)

🛠️ 검증에서 잡힌 정정 3건

  • StreetViewPreference는 {BEST, NEAREST}뿐 — RADIUS는 없다. radius는 별도 숫자 필드(기본 50m)
  • 요청의 source는 deprecated → 복수형 sources:[StreetViewSource.OUTDOOR]로 (preference가 대체하는 게 아님)
  • StreetViewSource는 DEFAULT | GOOGLE | OUTDOOR 3값. 상태값은 OK / ZERO_RESULTS / UNKNOWN_ERROR

지도 회전(map.setHeading)으로 시선을 미니맵에 반영하려면 mapId가 붙은 벡터 지도여야 함(래스터 지도에선 무동작). 마커는 Marker(2024-02 deprecated) 대신 AdvancedMarkerElement 권장(mapId 필요).

webui/index.html — 2분할 스켈레톤

<!-- #top=로드뷰(50%), #bot=지도(50%). 키는 서버가 GOOGLE_MAPS_JS_API_KEY로 주입 -->
async function initSplit(cfg){
  const {Map} = await google.maps.importLibrary("maps");
  const {StreetViewPanorama, StreetViewService, StreetViewPreference, StreetViewSource}
        = await google.maps.importLibrary("streetView");
  const pos = {lat: cfg.lat, lng: cfg.lng};

  const map  = new Map(top_el("bot"), {center:pos, zoom:14, mapTypeId:"hybrid"}); // 지형 식별
  const pano = new StreetViewPanorama(top_el("top"), {
      position:pos, pov:{heading:cfg.heading ?? 0, pitch:cfg.pitch ?? 0},
      zoom:1, motionTracking:false, linksControl:true});
  map.setStreetView(pano);                       // ← 두 패널 연결(페그맨/이동/오버레이 공유)

  // 카카오 getNearestPanoId(pos,80)의 대응물
  const svc = new StreetViewService();
  const req = cfg.pano ? {pano:cfg.pano}
      : {location:pos, radius:50, preference:StreetViewPreference.NEAREST,
         sources:[StreetViewSource.OUTDOOR]};   // sources 복수형(정정)
  try { const {data} = await svc.getPanorama(req); pano.setPano(data.location.pano); }
  catch { console.warn("ZERO_RESULTS — 커버리지 없음(바다/오지)"); }

  const sync = () => {                            // 이동하면 지도/state 동기화
    const p = pano.getPosition(); if(!p) return;
    map.setCenter(p);
    window.__state = {lat:p.lat(), lng:p.lng(), pano:pano.getPano(),
                      ...pano.getPov(), zoom:pano.getZoom()};  // 캡처 버튼이 읽음
  };
  pano.addListener("position_changed", sync);
  pano.addListener("pov_changed", sync); sync();
}

"보고 있는 그 장면"을 스크린샷

왜 브라우저 캔버스 캡처가 불가능한가. 구글 지도/스트리트뷰는 WebGL로 렌더되고 타일이 교차출처(CORS 헤더 없음)라 캔버스의 origin-clean 플래그가 꺼진다("tainted canvas"). 그 뒤 toDataURL()·toBlob()·getImageData()는 SecurityError를 던지고, html2canvas는 DOM만 재그리므로 지도 영역이 빈다. → 캡처는 전량 서버측 재렌더로 처리한다.

🅰️ Playwright 헤드리스 기본·고충실

프론트가 보낸 {pano,heading,pitch,zoom}으로 로컬 HTML을 렌더 → page.screenshot(). render_roadview.py의 LocalServer + wait + clip 루프를 그대로 쓰고 SDK만 구글로 교체. 로드뷰+지도를 한 페이지에 쌓으면 2분할 합성이 스크린샷 한 방에 나온다.

Architecture · stack

YCollector를 그대로 미러링한 스택

Python + uv + 경량 로컬 웹서버(FastAPI)가 단일 페이지 webui를 서빙 — YCollector가 "가장 가벼움"으로 미는 형태. Tauri/React 프런트는 후순위(UrlPasteBar.tsx 템플릿 재사용). 로컬 서버 우선은 취향이 아니라 필수 — 구글 SDK는 실제 http 오리진을 요구한다.

Risks · Google Maps Platform ToS

법적·기술 제약 (검증에서 가장 무거운 축)

항목내용대응등급
이미지 캐싱 금지스트리트뷰 이미지의 사전추출·인덱싱·저장·캐싱은 금지. 저장 허용 예외는 pano_id·place_id뿐("limited caching" 아님)캡처는 로컬·임시·비재배포 아티팩트로만. 서버엔 pano_id·POV·좌표·분석텍스트만 영속화높음
pano_id 불안정ToS상 저장은 허용이나 문서상 "ID는 시간이 지나면 바뀜 — 영속화 말 것", 옛 ID는 404 가능lat/lng를 durable anchor로 저장, pano_id는 갱신 가능한 최적화로 취급중간
대량 다운로드/경쟁 데이터셋타일 대량 수집·트레이싱으로 파생 데이터셋 구축 금지, 구글 콘텐츠를 비-구글 지도 옆/위에 표시 금지인덱싱 목적 수집 금지, 로드뷰 패널을 비-구글 베이스맵과 나란히 두지 않음중간
귀속(attribution)이미지에 박힌 "Google" 로고·워터마크를 크롭·제거 금지캡처 clip에 로고 유지중간
지오게서 페어플레이라이브 라운드 중 사용은 부정행위 → 계정 정지복기용 도구로 명시, 인게임 세션/내부 JSON 재사용 안 함(ToS 민감)높음
프라이버시얼굴·번호판은 Google이 블러개인 재식별 시도 금지 — 프롬프트 + 후처리 필터 이중 가드높음
키 제한 불일치리퍼러 제한 JS키는 서버 GET에서 무효, 미등록 포트는 RefererNotAllowedMapError2키 모델(브라우저 리퍼러 / 서버 IP), 8080·8000·80 등록중간
커버리지 공백바다·오지·미지원국은 ZERO_RESULTS무료 metadata로 선확인, no_pano 분기 처리(render_roadview.py 동일)낮음
비용/쿼터2025-03-01 개편으로 $200 단일 크레딧 폐지 → SKU별 무료 한도. Dynamic Street View는 Pro SKU, Static은 30k QPM·서명 권장metadata 선확인·pano 캐시·budget_usd 캡. 무료 한도 수치는 라이브 요금표 재확인중간
Playwright 타일 타이밍settle 대기 없으면 반쯤 로드된 파노 스크린샷wait_for_function(__ready) + ~1800ms(render_roadview.py 값)낮음
한 줄 요약. "스트리트뷰 이미지는 캐시/저장/대량다운로드 불가 — pano_id만 저장 가능(그나마 불안정). 캡처는 로컬·임시·비재배포, durable key는 lat/lng." 이것이 이 프로젝트의 가장 법적으로 하중이 큰 제약이다.
